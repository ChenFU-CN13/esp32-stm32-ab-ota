# 实机验证记录与证据边界

本页把结论分成三类：有完整日志或明确故障注入的“已验证”、由用户实机确认但材料不完整的“用户确认”、尚未执行的“待验证”。这样可以避免把代码已实现写成实机已通过。

## 已验证

| 用例 | 结果 | 关键观察 |
|---|---|---|
| R0：旧基线迁移 | 通过 | 旧 APP 镜像 CRC、向量表与跳转日志均正常。 |
| R1：正常升级 | 通过 | 先备份旧 APP，再擦除/写入；整包 CRC 一致并跳转新 APP。 |
| R2：整体 CRC 失败 | 通过 | STM32 返回 `NACK 0x05`，ESP32 ABORT，Bootloader 恢复旧镜像。 |
| R3：传输中 ABORT | 通过 | STM32 ACK 后进入回滚，旧 APP 可重新启动。 |
| R4：升级中断电 | 通过 | 擦除阶段和数据阶段断电后，重启均可识别 `UPGRADING` 并恢复旧镜像。 |
| W0：正常启动接管 IWDG | 通过 | Bootloader 启动 IWDG，APP 接管后没有误复位。 |
| W1：完整 OTA 期间 IWDG | 通过 | 备份、擦除、传输、CRC 和跳转期间没有误触发看门狗。 |
| W2：停止喂狗故障注入 | 通过 | A 区擦除后停止喂狗，IWDG 复位，Bootloader 随后完成回滚。 |
| V4：ESP32 单独重启后的版本回查 | 通过 | ESP32 发送 `66 09 BB`，运行中的 STM32 APP 重新上报当前版本。 |
